# Arrow Escape 4.0 validation

Release scope: 300 fixed formal puzzles across ten chapters, eight separate practice boards, newcomer/experienced entry, staged hints, independent completion records, legacy achievement archive and preserved classic campaign. No backend, authentication service or new domain is introduced.

## Automated checks

- 57 tests pass, including all 308 boards' unit paths, non-overlap, self-ray checks, full solutions, target solutions, exact budgets, key identity, stage ranges, progression, hint restoration, classic behavior and legacy save migration.
- `npm run audit:levels` passes all 300 engine-derived role contracts, exact sharing masks, optional regions and selected reachable release witnesses. Recorded solution routes also replay successfully.
- `npm run reproduce:levels` recreates all 300 published layouts from their stored offline recipes with exact coordinate equality.
- TypeScript, lint, production Vinext/Cloudflare build and whitespace checks pass. The existing build reports a client chunk size warning; no dependency versions or deployment adapter were changed.
- Read-only code review identified and verified fixes for tutorial return checkpoints, paused lesson sequencing, classic hint preservation, the tutorial failure undo entry and saved hint explanations.

## Browser acceptance

Performed against isolated local origins, leaving the user's original game save untouched. Final runtime checks use the production Worker output, not only the development server.

- Newcomer entry, actual pointer hit on an arrow, T01 complete/next, T02 pause/reload and return to the formal checkpoint.
- Experienced entry at C031, chapter access without fake completion, contextual two-key explanation on C271, and all ten chapters through C300 visible in level selection.
- C031 three-heart failure, terminal reload, retry, all three hint stages and one actual goal-route victory: 15/18 moves, 25 ordinary arrows left, one formal completion recorded and only C032 additionally unlocked.
- Saved first-stage hint explanation remains visible after a production-page reload.
- T06 exhausts 11 moves with stars still present; closing the failure dialog retains the undo button, which restores one move and resumes play.
- 390×844 and 320×740 portrait layouts; C271's 74-arrow overview and readable key/lock markers when zoomed; scrolling stays inside the board and a drag does not remove an arrow. The desktop mouse drag is not a physical-phone touch test.
- Final 844×390 compact landscape layout places controls beside the board, keeps practice controls accessible and has no page overflow. Temporary viewport overrides are reset after acceptance. Browser error log for the production acceptance page is empty.

The authoring audit and browser checks do not establish perceived difficulty, enjoyment, retention or player completion rates. Novice and experienced player sessions remain the next calibration step. The 300 levels are fixed offline content, not infinite or per-player runtime generation.
